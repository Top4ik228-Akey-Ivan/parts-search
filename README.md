# Поиск автозапчастей

Клиентское приложение на React для подбора запчастей и аналогов через API
[Favorit Parts «Проценка»](https://lk.favorit-parts.ru/static/wsprice.pdf).

Демо приложения:
https://top4ik228-akey-ivan.github.io/parts-search/

## Как это работает

1. **Этап 1.** Пользователь вводит артикул и нажимает «Найти» (или Enter).
   Приложение запрашивает у API детали с этим номером и показывает список производителей.
2. **Этап 2.** При выборе производителя выполняется повторный запрос
   (номер + бренд + `analogues=on`). В таблице отображаются искомая деталь и её аналоги:
   название / производитель, цена, остаток.

## Стек

- React 19 (JavaScript, без TypeScript)
- Redux Toolkit + react-redux
- Bootstrap 5
- Vite

## Запуск

Требуется Node.js 20.19+.

```bash
npm install
cp .env.example .env   # в Windows: copy .env.example .env
npm run dev
```

В `.env` укажите ключ покупателя:

```
VITE_API_KEY=ваш-ключ
```

Для проверки подойдёт тестовый ключ из документации API.
Приложение откроется на `http://localhost:5173`. Для примера введите артикул `01089`.

> API работает по `http`, поэтому приложение рассчитано на локальный запуск.
> На `https`-хостинге браузер заблокирует запросы (mixed content).

## Структура

```
src/
  api/parts.js            запросы к API, обработка ошибок, нормализация данных
  store/partsSlice.js     состояние, thunks fetchBrands / fetchOffers
  store/index.js          настройка store
  components/
    SearchForm.jsx        поле ввода артикула
    BrandList.jsx         список производителей (этап 1)
    OffersTable.jsx       таблица предложений и аналогов (этап 2)
    Loader.jsx            индикатор загрузки
    ErrorAlert.jsx        вывод ошибок
```

## Принятые решения

- **Цена** берётся из `warehouses[].price`, а не из поля `price` верхнего уровня
  (по документации оно оставлено для совместимости). Показывается минимальная цена
  среди складов с остатком. Если складов нет, выводится «нет в наличии».
- **Остаток** это поле `count` (сумма по всем складам).
- **Поиск по кнопке или Enter**, а не на каждый символ: у API есть квота запросов.
- **Обработка состояний:** загрузка, ошибка и пустой результат реализованы отдельно
  для каждого этапа. Сетевые сбои, HTTP-ошибки, ошибки API (`error` в ответе)
  и «пустая структура» при ненайденной детали приводятся к понятным сообщениям.
- **Гонка запросов:** ответ устаревшего запроса игнорируется (сравнение `requestId`
  в reducer), поэтому быстрый повторный поиск или выбор бренда не перезапишет результат.
- Спецсимволы в артикуле и бренде экранируются автоматически (`URLSearchParams`).
